### 주소창에 도메인을 입력하면 일어나는 일

#### 1. 도메인 네임의 DNS 조회

사용자가 입력한 도메인 네임을 IP 주소로 변환하기 위해 DNS(Domain Name System) 조회 과정 시작

1. **브라우저 캐시 확인**

   - 브라우저는 최근에 방문한 웹사이트들의 DNS 정보를 캐시에 저장
   - 입력한 도메인에 대한 IP 주소가 캐시에 존재하면, 해당 정보를 사용

2. **운영 체제(OS) 캐시 확인**

   - 브라우저 캐시에 정보가 없으면, 운영 체제의 DNS 캐시를 확인

3. **로컬 DNS 서버 질의**

   - OS 캐시에도 정보가 없으면, 네트워크 설정에 따라 지정된 로컬 DNS 서버(일반적으로 ISP 제공)로 질의
   - 로컬 DNS 서버는 자체적으로 캐시를 유지하여 이전 질의의 결과를 저장하고, 필요시 이를 반환

4. **재귀적 질의 수행**
   - 로컬 DNS 서버가 해당 도메인에 대한 IP 주소를 모르는 경우, DNS 질의가 재귀적으로 수행
   - **루트 DNS 서버**: 먼저 루트 서버에 질의하여 도메인의 최상위 정보를 획득
   - **TLD 서버**: 루트 서버가 반환한 정보를 사용해 TLD(Top Level Domain, 예: .com) 서버에 질의
   - **권한 있는 DNS 서버**: 최종적으로 특정 도메인(예: google.com)에 대한 정보를 관리하는 권한 있는 DNS 서버에 도달하여 IP 주소를 획득

#### 2. IP 주소 획득 및 HTTP 요청 준비

DNS 조회를 통해 얻어진 IP 주소를 기반으로 브라우저는 HTTP 요청을 전송하기 위해 네트워크 연결 준비

1. **TCP 연결 설정**

   - 브라우저는 서버와 통신하기 위해 TCP 연결 설정
   - **3-way handshake** 절차를 통해 연결 성립
     1. 브라우저가 서버에 SYN 패킷 전송
     2. 서버는 SYN+ACK 패킷으로 응답
     3. 브라우저가 ACK 패킷을 보내 연결이 완료

2. **SSL/TLS 핸드쉐이크 (HTTPS의 경우)**
   - 사용자가 HTTPS를 사용하는 웹사이트를 요청한 경우, SSL/TLS 프로토콜을 사용해 암호화된 연결을 설정
   - 서버의 인증서를 검증하고 세션 키를 교환

#### 3. HTTP 요청 전송 및 서버 응답

1. **HTTP 요청 생성**

   - 브라우저는 사용자가 입력한 URL을 바탕으로 HTTP 요청 메시지 생성
   - 이 메시지에는 요청 메서드(GET, POST 등), 헤더 정보, 쿠키 등이 포함

2. **HTTP 요청 전송**

   - 생성된 요청 메시지는 IP 주소와 연결된 서버로 전송

3. **서버 응답 처리**
   - 서버는 요청을 처리, HTTP 응답 메시지를 생성하여 브라우저에 반환
   - 이 메시지에는 상태 코드(예: 200 OK), 응답 헤더, 콘텐츠(HTML, CSS, JavaScript 등)포함

#### 4. 브라우저의 응답 처리 및 렌더링

1. **HTML 파싱**

   - 브라우저는 서버로부터 전달받은 HTML 문서를 파싱하여 DOM을 생성

2. **CSSOM 생성**

   - HTML 문서에서 참조된 CSS 파일을 다운로드하고 이를 파싱하여 CSSOM을 생성

3. **JavaScript 처리**

   - HTML 문서에 포함된 JavaScript 파일을 다운로드하고 실행

4. **렌더 트리 생성 및 화면 렌더링**
   - DOM과 CSSOM을 결합하여 렌더 트리를 생성
   - 레이아웃 계산(Layout)과 페인팅(Painting)을 거쳐 사용자 화면에 최종적으로 렌더링
