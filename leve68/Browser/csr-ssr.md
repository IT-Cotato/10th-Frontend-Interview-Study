## 싱글 페이지 애플리케이션 (SPA)

### 개요

- 처음에 하나의 HTML 페이지를 불러오고, 사용자의 상호작용에 따라 필요한 부분만 동적으로 업데이트하는 방식
- 새로운 페이지를 로드하지 않고 빠르게 반응하여, 부드럽고 일관된 사용자 경험을 제공

### 리액트에서의 싱글 페이지 애플리케이션 (SPA)

- 리액트는 SPA 구조에서 많이 사용되는 프레임워크로, 처음에 하나의 HTML 파일을 로드하고 이후 컴포넌트 기반으로 동적 업데이트를 수행
- 라우팅은 클라이언트에서 관리되며, `react-router`와 같은 라이브러리를 통해 URL 변경에 따라 필요한 컴포넌트만 로드하여 화면을 업데이트

### 특징

- **최초 로드**: 초기 접속 시 필요한 모든 리소스(HTML, CSS, JavaScript)를 한 번에 로드
- **동적 콘텐츠**: 이후 페이지 이동 시 서버에서 전체 페이지가 아니라 필요한 데이터만 요청하고, JavaScript로 화면 일부만 업데이트
- **장점**: 화면이 새로고침 없이 빠르게 반응하여, 네이티브 애플리케이션과 유사한 사용자 경험 제공
- **단점**: 초기 로드 시간이 길고, 검색 엔진 최적화(SEO)가 어려울 수 있음

## 클라이언트 사이드 렌더링 (CSR)

### 개요

- 클라이언트(브라우저)에서 JavaScript를 통해 화면을 렌더링하는 방식
- 서버는 데이터를 제공하고, 렌더링의 대부분은 클라이언트에서 처리

### 리액트에서의 클라이언트 사이드 렌더링 (CSR)

- 리액트는 기본적으로 CSR 방식을 사용해 브라우저에서 컴포넌트를 렌더링하고 DOM 업데이트를 수행
- 초기에는 `index.html`과 JavaScript 번들 파일을 로드하고, 이후 모든 렌더링 작업은 클라이언트에서 수행

### 특징

- **최초 로드**: 서버가 HTML, CSS, JavaScript 등의 리소스를 한 번에 전달, 이후 브라우저가 이를 로드해 화면 구성
- **렌더링 방식**: 추가 서버 요청 없이 필요한 데이터만 API를 통해 받아 JavaScript로 화면 업데이트
- **장점**: 페이지 이동 시 전체 페이지를 다시 로드하지 않아 빠른 반응 속도 제공
- **단점**: 검색 엔진 최적화(SEO)에 불리하고, JavaScript를 지원하지 않는 브라우저에서 작동하지 않을 수 있음

---

## 서버 사이드 렌더링 (SSR)

### 개요

- 사용자가 페이지를 요청할 때마다 서버에서 HTML을 생성해 브라우저로 전달하는 방식
- 사용자는 요청 시점에 즉시 렌더링된 HTML을 받아 빠르게 로딩된 페이지를 볼 수 있음

### 리액트에서의 서버 사이드 렌더링 (SSR)

- 서버에서 HTML을 생성하여 클라이언트에 전달하는 방식으로, 리액트는 `Next.js` 같은 프레임워크를 통해 SSR을 지원
- 페이지 요청 시 서버에서 컴포넌트를 렌더링하고, HTML 결과를 브라우저에 전달하여 초기 로딩 속도와 SEO 성능을 개선

### 특징

- **페이지 요청**: 사용자가 페이지를 요청할 때마다 서버는 새로운 HTML을 생성하여 응답
- **SEO 최적화**: 브라우저가 JavaScript를 실행하지 않아도 콘텐츠가 렌더링된 상태로 전달되어, 검색 엔진에 최적화되어 있음
- **장점**: 초기 로딩 속도가 빠르고, SEO에 유리
- **단점**: 서버 부하가 커질 수 있고, 동적인 상호작용이 많은 페이지에서는 CSR보다 느릴 수 있음

---

## SPA, CSR, SSR의 선택 기준

- **SPA**: 사용자 경험이 중요한 애플리케이션에 적합하며, 서버 부하가 적고 빠른 화면 전환이 필요한 경우에 사용
- **CSR**: 데이터와 상호작용이 많고 화면 전환 속도가 중요한 애플리케이션에 유리
- **SSR**: 콘텐츠 위주의 웹사이트나 SEO가 중요한 페이지에서 효과적이며, 검색 엔진 친화적인 웹사이트에 적합

---

## 리액트에서의 혼합 렌더링 방식

### 개요

- `Next.js`를 사용하면 SSR과 CSR을 혼합해 사용 가능
- 초기 로딩은 서버에서 렌더링한 HTML을 전달해 빠른 로딩과 SEO를 보장하고, 이후 클라이언트에서 상호작용이 발생하면 CSR로 전환하여 빠른 반응 속도를 제공

### 예시

- **Static Site Generation (SSG)**: 자주 변경되지 않는 페이지는 빌드 시 HTML 파일을 생성해 캐싱, 매우 빠른 로딩 속도를 제공
- **Incremental Static Regeneration (ISR)**: 일정 시간마다 정적 페이지를 갱신하여 최신 콘텐츠를 제공
- **CSR로 전환**: 페이지 이동 후 데이터 요청 시 클라이언트에서 데이터를 받아 화면을 업데이트하며 CSR의 장점 활용

### 장점

- 초기 로딩 속도와 SEO 성능을 높이면서도, 이후 상호작용에서 CSR의 유연성과 빠른 반응성을 유지 가능
