# 브라우저와 서버 간의 통신 과정

웹 브라우저는 사용자가 입력한 URL을 기반으로 서버에 요청을 보내고, 서버에서 받은 데이터를 해석하여 웹 페이지를 렌더링하는 역할을 수행한다.

## 1. 주소창에 입력한 텍스트 확인 (검색어 vs URL)

브라우저는 사용자가 입력한 텍스트가 **URL**인지 **검색어**인지 판단.

- **검색어**: 브라우저는 설정된 검색 엔진의 URL에 검색어를 포함한 주소로 페이지를 이동시킨다.
- **URL**: 브라우저는 URL을 기반으로 네트워크 호출을 실행한다.

## 2. DNS Lookup (도메인 이름 → IP 주소)

사용자가 URL을 입력한 경우, 브라우저는 사이트에 접속하기 위해 네트워크 요청을 보낸다. 웹 브라우저와 웹 서버는 서로 다른 컴퓨터에 위치하기 때문에, 브라우저가 웹 서버에 연결하려면 해당 서버의 주소를 알아야 한다.

브라우저는 사용자가 쉽게 기억할 수 있도록 `google.com`과 같은 도메인 이름을 사용하지만, 실제로 서버와 통신하기 위해서는 이 도메인에 대응하는 IP주소가 필요하다. 이를 위해 DNS(Domain Name Server)를 사용하여 도메인 이름을 IP 주소로 변환한다.

### 캐시조회

브라우저는 네트워크 요청을 보내기 전에 캐시에서 이미 도메인에 대한 IP 주소가 저장되어 있는지 확인

1. **브라우저 캐시**: 브라우저 내부에 저장된 IP 주소를 확인.
2. **OS의 hosts 파일**: 로컬 설정된 IP와 도메인 매핑 확인.
3. **OS의 DNS 캐시**: 운영체제 레벨에서 이전에 요청된 IP 주소 확인.
4. **라우터 캐시**: 라우터에 저장된 DNS 정보 조회.
5. **ISP의 DNS 캐시**: 인터넷 서비스 제공자가 저장한 정보 확인

### 📌 DNS 쿼리

캐시에서 IP 주소를 찾지 못하면 브라우저는 **로컬 DNS 서버**로 요청 전송. 로컬 DNS 서버는 다음과 같은 과정으로 IP를 찾는다.

1. **Root 네임서버**: 도메인 최상위 계층(`.`)에 대한 정보를 반환.
2. **TLD 네임서버**: 도메인의 최상위 도메인(예: `.com`) 정보를 반환.
3. **Authoritative 네임서버**: 도메인에 최종 매핑된 IP 주소를 반환.

이 과정을 **Recursive Query**라고 한다.

### 참고) Iterated query

: 클라이언트가 DNS 서버에 요청을 보내면, DNS 서버는 클라이언트에게 **다음으로 질의할 DNS 서버 정보를 반환**

- 클라이언트가 각 DNS 서버에 대해 직접 요청을 보내며, 최종 IP 주소를 스스로 찾는다.
- DNS 서버는 자신의 데이터베이스에 있는 정보만 제공하며, 다른 서버에 직접 요청하지 않는다.

| 특징              | Recursive Query                                 | Iterative Query                                  |
| ----------------- | ----------------------------------------------- | ------------------------------------------------ |
| 요청 처리 방식    | DNS 서버가 최종 결과를 반환                     | 클라이언트가 단계별로 요청하며 최종 결과를 구함  |
| 클라이언트의 부담 | 적음 (한 번의 요청만 필요)                      | 많음 (여러 서버에 직접 요청 필요)                |
| DNS 서버의 부담   | 상위 DNS 서버의 부담 높음 (모든 과정 처리)      | 낮음 (자신의 데이터만 반환)                      |
| 속도              | 상대적으로 느릴 수 있음 (서버 부하에 따라 다름) | 상대적으로 빠를 수 있음 (클라이언트가 직접 요청) |
| 사용 사례         | 로컬 DNS 서버, ISP DNS 서버                     | 클라이언트가 직접 DNS 처리 시                    |

## 3-1. IP Routing

DNS에서 IP 주소를 얻은 후, 브라우저는 라우터를 통해 서버로 데이터를 전송. 라우터는 **라우팅 테이블**을 사용해 데이터가 서버 네트워크까지 도달할 최적의 경로를 결정.

## **3-2. ARP를 통해 해당 서버의 MAC 주소 알아내기**

같은 네트워크 내에서 통신할 때는 **MAC 주소**를 사용. 브라우저는 **ARP(Address Resolution Protocol)**를 사용하여 서버의 MAC 주소를 확인

## **4. TCP 소켓 연결**

서버와의 통신을 위해 **TCP 연결**을 설정. 이는 **3-Way Handshake** 과정을 통해 이루어진다.

1. **클라이언트**가 **SYN(Synchronize)** 패킷을 전송.
2. **서버**가 **SYN-ACK(Acknowledge)** 패킷을 응답.
3. **클라이언트**가 **ACK** 패킷을 전송하여 연결을 완료.

## **5. HTTP(s) 프로토콜을 통해 통신**

TCP 연결이 완료되면 브라우저는 **HTTP 요청**을 보낸다. 이 요청은 클라이언트가 원하는 리소스를 서버에 요청하는 메시지.

- 서버는 요청을 수신하고 클라이언트가 요청한 데이터를 준비하여 **HTTP 응답**을 반환합니다.
- 응답에는 HTML, CSS, JavaScript, 이미지 파일 등이 포함됩니다.

## **6. 브라우저 랜더링 및 통신 종료**

브라우저는 서버에서 받은 HTML, CSS, JavaScript 등의 리소스를 기반으로 웹 페이지를 렌더링.

1. **HTML 파싱**: HTML 코드를 DOM(Document Object Model)으로 변환.
2. **CSS 파싱**: 스타일 정보를 계산해 렌더 트리를 생성.
3. **JavaScript 실행**: 페이지 동작을 활성화.
4. **렌더 트리 레이아웃**: 페이지 구조를 계산.
5. **페인팅**: 화면에 요소를 그리기.

서버에서 필요한 데이터를 모두 받은 후, 브라우저는 TCP 연결을 종료. 이는 **4-Way Handshake** 과정을 통해 이루진다.
